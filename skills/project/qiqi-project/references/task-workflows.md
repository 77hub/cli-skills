# 任务工作流与参数边界

## 先确定任务意图

- **项目任务**：归属明确 `Project:<id>`。项目不唯一时先用 `seek` 或 `find list Project` 消歧，并用 `records get` 核对。
- **日常任务**：没有项目和父任务。用户表达项目工作但缺少项目时，应先定位项目，不能省略项目引用来绕过。
- **子任务**：依附明确 `WorkTask:<id>`。父任务是层级上下文，不复制其状态、组织或其它系统信息。

负责人、父任务或扩展字段不明确时，使用 qiqi 发现对象、字段和值。模糊候选即使只有一条，也不能证明姓名或任务名称全局唯一。

## 参数边界

项目与任务引用是位置参数，其余业务字段是选项：`project task create` 后可跟项目引用，`project task update`、`project task start` 与 `project task finish` 后必须跟任务引用。父任务通过 `--parent` 选项传入。不要把位置参数写成 `--project` 或 `--task`。

具体 option、必填性和限制以目标叶子命令 `--help` 为准。稳定业务意图包括：

- `name`：任务要完成的工作，不承载项目、人员或状态编码。
- `owner`：负责人 `User:<id>`；姓名只用于发现候选，确认唯一后再传稳定引用。
- `scheduled-start` / `scheduled-finish`：任务计划自然日，使用 `YYYY-MM-DD`；开始日不得晚于完成日。
- `description`：任务说明。
- `notes`：备注。
- `additional`：当前企业的任务扩展字段对象，只包含已经确认的业务字段。

项目 `Project:<id>` 和父任务 `WorkTask:<id>` 用于确定任务结构，不放入 `additional`。同时给出项目和父任务时，两者必须一致。

不要主动提交任务状态、单据状态、项目关系、父任务关系、来源、审计、组织、单据配置或计算字段。返回的 `RecordRef`、状态和单据阶段只用于说明结果或后续工作，不回填进业务参数。

## 创建

先运行 `project task create --help`，再按当前定义创建：

- 项目任务传项目 `RecordRef`。
- 子任务传父任务 `RecordRef`；同时传项目时必须与父任务所属项目一致。
- 日常任务只在用户明确表达无项目、无父任务时省略两者。
- 确认名称、负责人、计划日期和必要扩展字段，只提交最小参数。

创建成功必须以返回的 `WorkTask:<id>` 和业务结果为准。返回草稿只表示任务记录已创建，不表示已提交、已开始或已完成。批量创建时逐条确认前一条结果；出现状态未知后停止继续创建相同任务。

## 修改

使用 `project task update <WorkTaskRef>` 修改名称、负责人、计划日期、说明、备注或当前允许的扩展字段。

- 只发送发生变化的参数。
- 不改变所属项目或父任务。
- 不推进任务状态，不设置实际日期。
- 当前状态不允许修改时说明业务拒绝，不改用扩展字段绕过。

## 开始与完成

任务执行只使用 Project 专用命令：

```bash
qiqi project task start WorkTask:<id> [--actual-start <YYYY-MM-DD>]
qiqi project task finish WorkTask:<id> [--actual-start <YYYY-MM-DD>] [--actual-finish <YYYY-MM-DD>]
```

实际 option 以当前叶子命令帮助为准。实际开始和实际完成是业务自然日，只能通过以上命令形成；不要通过 `project task update` 或扩展字段提前填写，也不要把计划日期自动复制为实际日期。

开始或完成命令中不夹带名称、负责人或扩展字段。不得使用 `do-action` 开始或完成 Project 任务，也不得直接改写任务状态或实际日期。

## 子任务批量操作的排队纪律

明确对多个子任务执行开始、完成、提交、撤回或其它可能间接更新主任务的写操作时，不要并发发起。多个子任务可能共同更新主任务或共同上级任务的状态与汇总事实，并行执行容易形成互斥和结果不确定。

1. 先确认每个子任务的父任务关系，并按会影响的同一主任务或共同上级任务分组。
2. 每组建立 Agent 侧队列，逐条串行发送原有 qiqi 命令或动作；不要假设存在额外的队列命令。
3. 前一项得到明确成功或失败结果，并完成必要核查后，再处理下一项。
4. 前一项出现超时、定义过期、连接中断或状态未知时，暂停该组队列；确认结果前不继续后续项，也不重试原操作。
5. 分项报告“待处理、处理中、已完成、失败、状态未知”；进入队列或命令已发送都不等于操作完成。

不同主任务分组也只在当前产品明确支持并行，且能够确认不会影响共同上级事实时才考虑并行；默认采用串行处理。
## 歧义、失败与核查

- 项目、人员或父任务有多个候选：展示有限候选并请用户选择。
- 字段不存在或值无效：重新读取当前帮助和元数据，不发明包装字段。
- 当前状态不允许命令：说明状态事实和被拒绝的意图，不直接改写状态。
- 定义过期：重新读取叶子命令帮助，重新检查参数，不自动重放。
- 超时、连接中断或结果不明确：按项目、任务引用、唯一业务事实和时间窗口查询；仍无法确认时报告状态未知，不直接重试。
