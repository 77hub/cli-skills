# 工时登记

## 工时事实

`project work-hours log` 登记当前人员在一个或多个业务自然日对项目或任务的投入，并按平台规则形成工时单记录。工时不自动证明任务进度、任务完成或财务成本。

登记前确认：

1. 项目 `RecordRef` 唯一且当前业务允许登记工时。
2. 任务存在时，它属于同一项目；用户只表达项目级工作时不创建占位任务。
3. `work-date` 是明确的业务自然日。
4. 每条明细在 `hours` 与 `days` 中恰好选择一种，并提供正数。
5. 工作内容客观描述已经投入的工作，不把计划写成完成事实。

## 使用数据文件

先读取 `project work-hours log --help`。工时包含数组，优先使用 `--data-file`，避免内联 JSON 的 shell 转义问题。数据文件结构以当前帮助为准，例如：

```json
{
  "items": [
    {
      "project": "Project:<id>",
      "task": "WorkTask:<id>",
      "work-date": "2026-07-30",
      "hours": 8,
      "work-content": "完成已实际投入的工作"
    }
  ],
  "remarks": "可选的工时单备注"
}
```

任务级明细使用 `task`；项目级明细省略 `task`。不要同时传 `hours` 和 `days`。租户扩展字段只放入当前帮助允许的 `additional` 位置，不增加自定义包装层，不复制状态、来源或审计字段。

## 结果和失败

登记成功以最终返回的工时单引用、明细结果和业务阶段为准。若返回草稿，只报告草稿已经形成；不表述为已经提交、审批或形成财务成本。

一组工时作为一个业务请求理解。任一项目、任务、日期、数量或扩展字段校验失败时，不把未得到明确成功证明的部分描述为已写入。调用超时或状态未知时按当前用户、项目、任务、日期和时间窗口核查近期工时，确认前不重复登记。
