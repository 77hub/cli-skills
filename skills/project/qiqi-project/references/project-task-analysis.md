# 项目任务分析

## 最少校准

先确认项目、任务层级、计划窗口、状态时点和负责人范围。用户要求“进度”“逾期”或“健康度”时，确认采用的字段定义和观察时点。

## 权威事实

计划开始和完成日期、实际开始和完成日期、任务状态、单据状态、工时投入与依赖关系是不同事实。工时不能单独证明进度，单据已提交也不能证明任务已完成。

逾期、完成率和进度只按当前可确认字段或产品权威口径判断：

- 没有明确截止日期，不判断逾期。
- 没有完整任务总量，不输出项目完成率。
- 没有基线或权威进度字段，不从工时比例推算进度。
- 父子任务汇总规则不明确时，分别展示，不自行加总。

## 查询与完整性

1. 用 qiqi 确认唯一项目及 `WorkTask` 的当前字段、时间语义和引用关系。
2. 根据用户范围选择 `find view my-tasks`、`find view my-teams-tasks` 或 `find list WorkTask`。
3. 使用项目 `RecordRef` 和当前可查询字段限定范围，持续分页直到 `hasMore` 为 `false`。
4. 大输出读取完整文件；对状态未知、权限不可见、缺少依赖或缺少计划日期的任务单独标记。
5. 当前字段或权限无法形成完整任务集合时，说明只分析已确认记录，不声称覆盖整个项目。

## 结果结构

- 项目、观察时点、任务范围和口径。
- 正常、临期、逾期、未排期或状态异常的任务事实。
- 每项异常的任务引用、负责人、计划与实际日期、可确认状态。
- 数据缺口和需要项目负责人判断的风险。
- 建议动作与事实分开呈现，不把建议写成系统状态。

避免只看单据状态、用当前日期覆盖观察时点、按任务名称合并记录，或在任务集合不完整时输出伪精确百分比。
