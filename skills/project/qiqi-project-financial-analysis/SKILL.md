# 企企服务业ERP项目经营分析

本技能从财务事实视角揭示项目经营，不替企业预设唯一经营模型。项目预算是可选能力；没有编制项目预算的企业，仍可沿合同、收入确认、开票、应收应付、收付款、费用和人力成本分析项目。

## 初始假设与边界条件

- 项目是财务事实的归集维度。多数经营单据应以明细行的项目和金额为准；一张单据包含多个项目时，表头项目可能为空。
- 合同、确认、开票、应收应付、收付款和核算是不同业务阶段，金额相同也不能互相替代。
- “利润”“收入”“成本”“执行”没有脱离企业口径的唯一公式。只有系统提供权威结果或用户确认公式时才计算派生指标。
- 标准对象、字段和报表只是运行时探索候选，不证明当前企业已启用、当前身份可见或当前查询通道可用。
- 本技能不处理计划、进度、资源安排、周报等项目执行管理；这些能力应由未来独立技能承接。
- 默认只读。用户没有明确要求写入时，不修改项目、项目预算或业务单据。

## 最简分析闭环

1. 确认唯一项目、观察期间、主子项目范围、财务组织、币种及含税或无税口径。
2. 只追问会改变结论的口径：用户关注项目预算、合同承诺、收入确认、开票、应收应付、现金实现，还是企业自定义指标。
3. 从用户的原始业务表述提取关键词，探索当前企业的对象、字段和自定义能力，不固定搜索“项目收入”“项目费用”或“项目预算”。
4. 按实际可用性选择最短证据路径：企业权威能力、标准业务事实、项目预算。
5. 分阶段展示事实；只有范围一致、关系可追溯且数据完整时才计算透明推导值。
6. 输出已确认事实、推导值、未知项和下钻入口，不把查询失败或空结果解释为零。

## 证据路径选择

1. **企业口径**：企业已有可发现、可查询且定义明确的经营报表、自定义对象或指标时，优先沿用并披露定义。
2. **标准业务事实**：查询合同、收入、费用、人力、开票、应收应付和资金事实，按阶段并列观察。这不是项目预算不可用时的降级结果。
3. **项目预算**：只有取得与项目、组织、期间、版本和币种匹配的预算证据时，才分析预算、占用、实际执行、总消耗和预算公式利润。

标准事实地图见 [business-fact-model.md](references/business-fact-model.md)，已验证查询见 [query-playbook.md](references/query-playbook.md)，项目预算与利润边界见 [budget-and-profit.md](references/budget-and-profit.md)。

## 查询与判断纪律

- 项目定位优先使用 `query list Project` 模糊查询；使用 `seek` 时必须限定 `--type Project`，且结果仍需用稳定 ID 核验。
- 根据用户使用的业务词发现对象与字段，再形成查询。对象可发现或可描述不等于通用记录查询可用。
- 单据默认只查询主单 `billStatus = BillStatus.effective`。只有用户明确要求其它状态，或目标业务事实必须采用其它状态时才调整并披露范围。
- 默认按明细对象的 `projectId` 归集并汇总明细金额，同时通过明细到主单的真实关联筛选主单状态与业务日期；不能只按表头项目查询。
- 明细求和优先服务端聚合；解释构成时再读取完整分页。只有元数据证明单据没有项目明细或项目只能位于主表时，才使用主表项目。
- 金额事实要保留主单状态、业务日期、组织、明细项目、币种和稳定记录身份。
- 汇总、合同累计字段和来源单据可能表达同一事实，未经关系核对不得重复累计。
- 主子项目、跨组织、多币种、红冲冲销、期初数据和未生效记录都可能改变结论，必须固定范围或列为缺口。

## 派生指标边界

允许计算的最小形式为：

```text
指标 = F(已命名的业务事实集合)
```

同时披露公式、事实阶段、项目范围、期间、组织、币种、税额口径、状态范围和缺失项。尤其禁止默认使用：

- 合同额作为收入；
- 开票额作为收入确认；
- 收款减付款作为利润；
- 工时直接作为人工成本；
- 预算总消耗作为实际发生；
- 当前未查到作为业务未发生。

## 结果结构

- 项目稳定引用、编码、名称及主子项目范围；
- 期间、组织、币种、含税或无税与状态口径；
- 项目预算、合同承诺、收入确认、开票、应收应付、费用成本、人力投入和收付款事实；
- 企业权威指标或透明推导值，以及公式和来源；
- 可下钻的对象、记录身份和异常差异；
- 权限、分页、查询能力、关联、状态和数据完整性缺口。

## 可省略的工程严谨性

用户只问单一事实且对象、项目、期间和口径明确时，只执行对应查询即可。只有需要跨域汇总、利润判断、趋势比较或风险结论时，才展开完整证据链和对账。
