# 对象发现、查询与完整性

## 选择发现路径

1. 不知道对象类型时，用 `objects` 按业务关键词取得当前 profile 的候选。
2. 已知对象但字段类型、时间语义或引用关系不清楚时，用 `describe fields <ObjectType>`。
3. 准备列表查询时，用 `describe list <ObjectType>` 查看常用查询字段和少量样例。
4. 只有名称、单号或人名片段时，用 `seek` 获取跨对象有限候选。
5. 已知对象和筛选条件时，用 `find list <ObjectType>` 查询集合。
6. 枚举、布尔或引用字段需要候选值时，用 `find values <ObjectType.field>`。
7. 已有稳定 `RecordRef` 时，用 `records get <RecordRef>` 读取完成任务所需的可见字段。

对象目录和缓存只产生候选，不证明当前服务端授权。租户之间可能有相似显示名但不同对象、字段和允许值，不凭经验跳过运行时发现。

## 字段与候选值

`describe fields` 是字段语义权威，但只描述当前公开的根字段；引用对象的候选记录用 `find values`，不要把引用显示名直接当 ID。

- 时间字段读取 `temporalKind`、`format` 和 `example`。
- 枚举字段先取得当前真实值，不把中文标题当枚举值。
- 引用字段先确认允许的对象类型，再取得稳定候选。
- 列表、结构化字段和引用字段不因重复读取样例而变成完整展开结果。
- 当前描述没有声明必填、可编辑或默认值时，不从样例推断这些属性。

## 候选与唯一性

`seek` 只搜索当前身份有权访问且已经接入的来源。即使只返回一条，也不能证明全系统唯一。

- 只读展示可用对象类型、标题、编码和 `RecordRef` 帮助用户消歧。
- 写操作必须使用用户给定的稳定引用、唯一业务编码或其它可验证关系确认目标。
- 无法证明唯一时请求用户选择，不默认使用第一条。

## 列表查询

先用 `describe list` 确认可查询字段，再使用 `find list`。简单条件遵循当前帮助中的 `field[:operator]=value` 语法；只使用 CLI 当前明确支持且能由字符串表达的操作符，不构造原始查询语言。

- 多个 `--where` 默认表示同时满足；复杂逻辑只有当前 CLI 帮助明确提供结构化输入时才使用。
- 不使用当前帮助中不存在的 `--query-file`。
- 只选择完成任务需要的字段，并使用稳定排序保证分页结果可解释。
- 持续读取 `offset/limit` 分页，直到 `hasMore` 明确为 `false`。
- 权限不可见、分页未结束、过滤口径未确认或输出文件未完整读取时，不声称完成全量统计。

## Views 与单记录

`describe view` 用于发现预置工作视图及其输出定义，`find view` 用于取得数据。View 的筛选语义由服务端定义，不把 View 标题或样例反推成对象状态条件。默认会提供关于`待我审批`、`我的任务`、`我的单据`类的基础工作视图。

`records get` 返回当前用户可见的业务字段，不保证包含全部明细、引用展开或动态动作（会以用户配置的表单模板作为展示字段集合）。需要动作时另用 `describe actions`；需要附件时另用 `records attachments`。

## 大输出

收到 `77hub.large-output` 包装时：

1. 将 `path` 视为完整 JSON 的本地位置。
2. 读取并解析该文件后再继续分析。
3. 可使用 `sha256` 核对完整性。
4. 不把 `summary`、`sample` 或终端截取内容当成完整结果。
